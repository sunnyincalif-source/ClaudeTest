# Dress rehearsal: from zero to a trace on real LeetCode

Use this after `LAUNCH_CHECKLIST.md` steps 1–3 (public repo, site deployed, `v1.0.0`
released). It needs a **clean machine** that has never had LeetTrace installed; a fresh user
account or a VM is fine. Use **only what the site tells you**. If you need anything that isn't
on the page, that's a bug in the page, so write it down.

Allow about 15 minutes. Do each step, then check what it says to check. Record each result as
✅ or ❌, with a screenshot of any ❌.

## Reporting what breaks

For every ❌, open an issue at `https://github.com/<you>/leettrace/issues` with:

- the step number, your OS and version, and your Chrome version (`chrome://version`);
- a screenshot;
- for anything inside LeetCode: the problem URL, plus any red errors from DevTools → Console
  (press F12);
- for app problems: the log file, `~/.leettrace/daemon.log` or `~/.leettrace/app.log`
  (`%USERPROFILE%\.leettrace\…` on Windows).

You can also paste those into this Claude Code session, which can be reopened from your
session history. The most likely fixes are small and local:

- the page reading in `apps/extension/src/content/leetcodePage.ts`;
- install copy in `apps/site/src/App.tsx`.

If your problem page isn't read correctly (step 12), save the real page so it becomes a
regression test:

1. Open DevTools → Console on that page.
2. Run `copy('<!doctype html>' + document.documentElement.outerHTML)`.
3. Paste the result into `apps/extension/e2e/fixtures/real-<slug>.html`.
4. Commit it. The fixture test suite picks it up automatically.
